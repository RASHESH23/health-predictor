# Health Predictor
Health Predictor is a browser-based diabetes-risk screening application.
It combines a static HTML, CSS, and JavaScript frontend with a FastAPI backend.
The backend loads a scikit-learn Gradient Boosting model trained on CDC BRFSS 2015 health indicators.
The application accepts 21 health, lifestyle, and demographic indicators.
It returns a probability estimate, risk information, factors, recommendations,
and a medical disclaimer.
This project is for education and health-risk screening only.
It is not a medical diagnostic system or a substitute for professional care.
## Features
- Browser-based diabetes-risk assessment form.
- Gradient Boosting probability prediction.
- Low, Moderate, and High backend risk bands.
- Reproducible model-training script.
## How it works
1. A user completes the assessment form.
2. The frontend validates required values and numeric ranges.
3. JavaScript sends JSON to the FastAPI prediction route.
4. Pydantic validates the request on the server.
5. The inference service restores the trained feature order.
6. The model calculates the positive-class probability.
7. The service applies the prediction threshold and risk bands.
8. The API returns the result and explanatory information.
9. The frontend renders the result and disclaimer.
The model prediction and explanatory text are separate.
The explanatory lists are generated by rules in the inference service.
Those rules do not modify the machine-learning prediction.
## Technology
- Python 3.10 or newer is recommended.
- The bundled environment records Python 3.14.2.
- FastAPI and Uvicorn provide the HTTP service.
- Pydantic validates the request schema.
- pandas builds model input data.
- scikit-learn provides the classifier.
- joblib serializes the model artifacts.
- HTML, CSS, and vanilla JavaScript provide the frontend.
- Google Fonts and Font Awesome are loaded from CDNs.
There is no dependency manifest; the installation commands list the dependencies used.

## Installation
Run commands from the repository root.
Create a fresh environment for a new machine:
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install fastapi "uvicorn[standard]" pydantic pandas numpy scikit-learn joblib
python -m pip install jupyter matplotlib seaborn
```
On Windows, use this activation command:
```powershell
.venv\Scripts\activate
```
The existing `env/` directory can be used on the original macOS or Linux machine:
```bash
env/bin/python -m pip install fastapi "uvicorn[standard]" pydantic pandas numpy scikit-learn joblib
```
Create a clean environment for other machines and deployment targets.
## Run the application
The API loads both model artifacts during import.
They must exist before the supported application can start.
They are currently stored in `models/diabetes/`.
Start the backend from the repository root:
```bash
env/bin/python -m uvicorn src.main:app --reload
```
With an activated `.venv`, use:
```bash
python -m uvicorn src.main:app --reload
```
The backend listens at `http://127.0.0.1:8000`.
In a second terminal, serve the frontend:
```bash
env/bin/python -m http.server 5500 --directory frontend
```
With an activated environment, the equivalent is:
```bash
python -m http.server 5500 --directory frontend
```
Open `http://127.0.0.1:5500` in a browser.
The frontend calls this hard-coded development URL:
```text
http://127.0.0.1:8000/predict/diabetes
```
Change `API_URL` in `frontend/js/diabetes.js` when the backend moves.

## Response and risk logic
A successful response includes:
- `success`: Whether the request completed successfully.
- `prediction`: Binary model decision, `0` or `1`.
- `probability`: Positive-class probability rounded to four decimals.
- `risk_level`: Backend risk band.
- `prediction_message`: Human-readable likelihood message.
- `key_factors`: Rule-based factors associated with increased concern.
- `positive_factors`: Rule-based favorable factors.
- `recommendations`: General, non-diagnostic suggestions.
- `disclaimer`: Medical screening disclaimer.
The binary prediction threshold is `0.25`.
The backend risk bands use separate boundaries:
| Probability | Backend risk level |
| --- | --- |
| `< 0.20` | Low |
| `0.20` to `< 0.40` | Moderate |
| `>= 0.40` | High |
A probability of `0.28` is therefore a positive binary prediction,
but its backend risk level is `Moderate`.
The two values should not be treated as interchangeable.
The frontend has separate display metadata logic.
For probabilities between 20% and 30%, its visual treatment can differ
from the backend label because the browser code uses its own thresholds.
Treat the API response as the authoritative machine-readable result.
## Model training
The training script reads:
```text
data/raw/diabetes_binary_health_indicators_BRFSS2015.csv
```
The CSV contains the `Diabetes_binary` target and 21 input features.
The script removes duplicate rows before splitting the data.
It uses an 80/20 stratified train/test split with `random_state=42`.
The classifier configuration is:
```text
GradientBoostingClassifier(
    n_estimators=100,
    learning_rate=0.1,
    max_depth=3,
    random_state=42,
)
```
The script prints accuracy, precision, recall, F1, ROC-AUC, PR-AUC,
a confusion matrix, and a classification report.
It writes the classifier to `models/diabetes/diabetes_model.pkl`.
It writes the exact feature order to `models/diabetes/feature_columns.pkl`.
Regenerate both artifacts with:
```bash
env/bin/python src/models/diabetes/train_final.py
```
Or, with an activated environment:
```bash
python src/models/diabetes/train_final.py
```
The inference service loads the artifacts at import time.
Missing or incompatible artifacts prevent the API from starting.
Only load joblib or pickle files from trusted sources.

## Explanations
The supported API calls `predict_diabetes` from `predict.py`.
That service calculates the probability and response factor lists.
It checks blood pressure, cholesterol, BMI, activity, cardiovascular history,
stroke history, general health, physical health, walking difficulty, and age.
Recommendations are general suggestions, not individualized medical advice.
`src/services/diabetes/explanation.py` is a separate helper.
It is not currently called by the supported `src.main:app` path.
Changing that file alone does not change the live API response.
## Troubleshooting
### API startup fails
Confirm that both model files exist:
```bash
ls models/diabetes/diabetes_model.pkl models/diabetes/feature_columns.pkl
```
Train the model if either file is missing.
Regenerate artifacts if a Python or scikit-learn version change causes load errors.
### Browser connection fails
Confirm Uvicorn is running on port `8000`.
Confirm the frontend server is running on port `5500`.
Confirm `API_URL` points to the active backend.
Inspect the browser console for request or CORS errors.
### Request validation fails
Open `/docs` and test the API directly.
Check that every field is present and uses the documented name.
Check that binary fields are integers from `0` through `1`.
Check that numeric values are within the documented ranges.
### Notebook cannot find the CSV
Launch Jupyter from the `notebooks/` directory.
### A port is already in use
Stop the process using the port or select another port.
For example:
```bash
env/bin/python -m uvicorn src.main:app --reload --port 8001
```
Update the frontend `API_URL` if the backend port changes.
## Limitations and security
- The model learns associations in the supplied BRFSS dataset.
- Its output is a screening estimate, not a diagnosis.
- Category encodings must be interpreted correctly.
- The local environment is machine-specific.
- Dependencies are not pinned by a repository manifest.
- Serialized artifacts must be trusted before loading.
- CORS currently permits all origins for development.
- Restrict CORS before any production deployment.
- The frontend uses a local URL configured in source code.
- CDN assets may be unavailable offline.
- No automated test suite is currently included.
- No authentication or rate limiting is configured.
- HTTP 500 responses currently expose internal exception text.
- Do not expose this development configuration directly to the internet.
## Development notes
The supported application is:
```text
src.main:app
```
A separate API exists under `src/api/`.
It exposes `/api/diabetes/predict` through `src/api/main.py`.
That path uses a looser schema and is not used by the frontend.
Treat it as a legacy or alternate implementation unless deliberately tested.
When changing features, update the dataset, saved feature order, schema,
frontend form, inference rules, and API documentation together.
A local smoke check should include:
```bash
env/bin/python -m uvicorn src.main:app --reload
curl http://127.0.0.1:8000/health
```
Then send one valid request to `/predict/diabetes`.
